# 🎓 Подготовка к защите проекта "Многопользовательский Филворд"

## 📋 Общая информация о проекте

**Название:** Word Search Multiplayer (Многопользовательский Филворд)  
**Тип:** Веб-приложение для игры в филворд с поддержкой многопользовательского режима  
**Технологический стек:** Next.js 16, React 19, TypeScript, tRPC, Drizzle ORM, Better Auth, PostgreSQL  
**Архитектура:** Clean Architecture с Dependency Injection  
**Покрытие тестами:** 117 unit-тестов (85%+ покрытие)

---

## 🏗️ Архитектура проекта

### Dependency Injection

**Файл:** `core/di/Container.ts`

DI Container управляет зависимостями между слоями:
- Регистрация сервисов и репозиториев
- Ленивая инициализация зависимостей
- Легкое тестирование через mock-объекты

**Преимущества:**
- ✅ Инверсия зависимостей (SOLID-D)
- ✅ Легко тестировать (mock dependencies)
- ✅ Гибкость (легко менять реализации)

### Repository Pattern

Все операции с БД идут через интерфейсы репозиториев:
- `GameRepository` — интерфейс для операций с игровыми сессиями
- `DrizzleGameRepository` — реализация с Drizzle ORM

### 🔹 База данных

#### `drizzle/schema.ts`
**Назначение:** Определение схемы базы данных (9 таблиц)

**Таблицы Better Auth:**
1. **`users`** — пользователи системы
   - `id` (UUID, PK) — уникальный идентификатор
   - `name` (TEXT) — имя пользователя
   - `email` (TEXT, UNIQUE) — email
   - `emailVerified` (BOOLEAN) — подтверждён ли email
   - `passwordHash` (TEXT) — хэш пароля
   - `image` (TEXT) — аватар
   - `createdAt`, `updatedAt` (TIMESTAMP) — временные метки

2. **`sessions`** — сессии пользователей
   - `userId` (FK → users.id) — ссылка на пользователя
   - `token` (TEXT, UNIQUE) — токен сессии
   - `expiresAt` (TIMESTAMP) — время истечения

3. **`accounts`** — OAuth аккаунты
   - `providerId` (TEXT) — провайдер (GitHub, Google)
   - `accessToken`, `refreshToken` — токены доступа

4. **`verifications`** — коды верификации email

5. **`userRoles`** — роли пользователей (user/admin)

**Таблицы игры:**
6. **`gameSessions`** — игровые сессии
   - `wordList` (TEXT[]) — список слов для поиска
   - `grid` (JSONB) — игровое поле 10×10
   - `gameMode` (ENUM: individual/team) — режим игры
   - `onTimeLimit` (BOOLEAN) — режим на время
   - `status` (ENUM: waiting/in_progress/finished)
   - `maxPlayers` (INTEGER) — макс. количество игроков
   - `duration` (INTEGER) — длительность в секундах
   - `rematchSessionId` (UUID) — ссылка на реванш
   - `hostUserId` (FK → users.id) — хост сессии

7. **`gamePlayers`** — игроки в сессии
   - `sessionId` (FK → gameSessions.id)
   - `userId` (FK → users.id) — ссылка на пользователя (опционально)
   - `name` (TEXT) — имя игрока
   - `isBot` (BOOLEAN) — является ли ботом
   - `color` (TEXT) — цвет игрока
   - `turnOrder` (INTEGER) — порядок хода
   - `firstWordTime` (INTEGER) — время первого слова (сек)
   - `team` (ENUM: red/blue/green/yellow) — команда
   - `difficulty` (ENUM: easy/medium/hard) — сложность бота
   - `wordsFound` (INTEGER) — количество найденных слов

8. **`foundWords`** — найденные слова
   - `sessionId` (FK → gameSessions.id)
   - `playerId` (FK → gamePlayers.id)
   - `word` (TEXT) — найденное слово
   - `startRow`, `startCol`, `endRow`, `endCol` (INTEGER) — координаты
   - `direction` (ENUM) — направление (horizontal/vertical/diagonal_down/diagonal_up)
   - `path` (JSONB) — полный путь координат (для змейки)
   - `foundAt` (TIMESTAMP) — время нахождения

9. **`matchHistory`** — история матчей
   - `sessionId` (FK → gameSessions.id)
   - `userId` (FK → users.id)
   - `playerName` (TEXT) — имя игрока
   - `wordsFound` (INTEGER) — количество слов
   - `firstWordTime` (INTEGER) — время первого слова
   - `rank` (INTEGER) — занятое место
   - `recordedAt` (TIMESTAMP) — время записи
   - **Уникальный индекс** на `sessionId` (только одна запись истории на сессию)

### 🔹 Core (Domain Layer)

#### `core/game/types.ts`
**Назначение:** Определение TypeScript типов для игрового домена

**Основные типы:**
- `GameStatus` — статус игры (waiting/in_progress/finished)

- `Direction` — направление слова (horizontal/vertical/diagonal_down/diagonal_up)

- `Coordinate` — координаты на поле {row, col}
- `Player` — игрок с полями: id, name, isBot, color, wordsFound, firstWordTime, team, difficulty, turnOrder, status, userId
- `GameSession` — сессия игры со всеми параметрами
- `FoundWord` — найденное слово с координатами и путём
- `CreateSessionInput`, `JoinSessionInput`, `SubmitWordInput` — DTO для операций

#### `core/game/GameRepository.ts`
**Назначение:** Интерфейс репозитория для операций с игровыми сессиями

**Методы интерфейса:**
- `createSession(input: CreateSessionInput): Promise<GameSession>`
- `getSession(id: string): Promise<GameSession | null>`
- `joinSession(input: JoinSessionInput): Promise<Player>`
- `submitWord(input: SubmitWordInput): Promise<FoundWord>`
- `getFoundWords(sessionId: string): Promise<FoundWord[]>`
- `finishSession(sessionId: string): Promise<void>`

**Принцип:** Инверсия зависимостей — бизнес-логика зависит от абстракции, а не реализации

#### `core/game/GameService.ts`
**Назначение:** Бизнес-логика игры (Domain Services)

**Ответственность:**
- Валидация бизнес-правил
- Координация между репозиторием и сущностями
- Обработка ошибок домена

**Методы:**
- `createSession()` — создание новой игровой сессии
- `joinSession()` — присоединение игрока
- `startGame()` — запуск игры
- `submitWord()` — отправка найденного слова
- `getResults()` — получение результатов
- `rematch()` — создание реванша

**Бизнес-правила:**
- Минимум 2 игрока для начала игры
- Только хост может начать игру
- Слово может найти только один игрок
- При равенстве очков побеждает тот, кто быстрее нашёл первое слово

#### `core/di/Container.ts`
**Назначение:** Dependency Injection Container

**Реализация:**
- Регистрация сервисов по ключам

#### `server/trpc/gameRouter.ts`
**Назначение:** tRPC процедуры для игровых операций

**Процедуры (8 штук):**

1. **`createSession`** (mutation)
   - Input: `{ maxPlayers, duration, gameMode, onTimeLimit }`
   - Output: `{ sessionId, grid, wordList, ... }`
   - Логика: генерация поля 10×10, создание записи в БД

2. **`joinSession`** (mutation)
   - Input: `{ sessionId, playerName, userId? }`
   - Output: `{ playerId, color, playersCount, isHost }`
   - Логика: проверка сессии, добавление игрока, назначение цвета

3. **`startGame`** (mutation)
   - Input: `{ sessionId }`
   - Output: `{ message, grid, playerCount }`
   - Логика: проверка что вызывающий — хост, запуск ботов в фоне

4. **`submitWord`** (mutation)
   - Input: `{ sessionId, playerId, word, startRow, startCol, endRow, endCol, direction, path? }`
   - Output: `{ success, error?, word?, playerScore?, results?, gameEnded }`
   - Логика: валидация слова, сохранение в БД, проверка окончания игры

5. **`getSessionState`** (query)
   - Input: `{ sessionId, playerId? }`
   - Output: полное состояние игры (grid, players, foundWords, teams, rematchSessionId)
   - Логика: получение всех данных для рендера, автозавершение по времени

6. **`setTeam`** (mutation)
   - Input: `{ sessionId, playerId, team }`
   - Output: `{ success, team }`
   - Логика: установка команды игрока (только в режиме ожидания)

7. **`addBot`** (mutation)
   - Input: `{ sessionId, botName, difficulty, team? }`
   - Output: `{ playerId, color, playersCount, difficulty, team }`
   - Логика: создание бота с заданной сложностью

8. **`rematch`** (mutation)
   - Input: `{ sessionId, playerId }`
   - Output: `{ sessionId: string }` — ID новой сессии
   - Логика: создание новой сессии с теми же параметрами, запросивший игрок становится хостом

9. **`removePlayer`** (mutation)
   - Input: `{ sessionId, playerId, targetPlayerId }`
   - Output: `{ success, removedPlayerId }`
   - Логика: удаление игрока из сессии (только хост, только в режиме ожидания)

10. **`getMatchHistory`** (query)
    - Input: `{ playerName, limit }`
    - Output: `{ history, stats }`
    - Логика: получение истории матчей игрока

**Вспомогательные функции:**
- `saveMatchHistory()` — сохранение статистики после завершения игры
- `calculateResults()` — вычисление результатов игры
- `calculateTeams()` — подсчёт очков команд

#### `server/bot.ts`
**Назначение:** Реализация игрового бота

**Класс `GameBot`:**
- `sessionId`, `playerId` — идентификаторы
- `minDelay`, `maxDelay` — диапазон задержки между ходами (мс)
- `accuracy` — вероятность правильного поиска (0-1)
- `skipChance` — вероятность пропуска хода
- `isActive` — флаг активности

**Методы:**
- `startFindingWords()` — основной цикл поиска слов
- `stopFindingWords()` — остановка бота
- `findWordsOnGrid()` — поиск всех слов на поле
- `findWordPath()` — поиск пути слова (змейка с 1 поворотом)
- `submitWord()` — отправка найденного слова в БД

**Уровни сложности:**
| Сложность | Min Delay | Max Delay | Accuracy | Skip Chance |
|-----------|-----------|-----------|----------|-------------|
| Лёгкий | 1600ms | 4000ms | 70% | 12% |
| Средний | 1000ms | 3000ms | 90% | 10% |
| Сложный | 600ms | 2000ms | 95% | 5% |

**Класс `BotFactory`:**
- Фабричный метод `createBot()` для создания ботов с заданной сложностью

#### `lib/word-search.ts`
**Назначение:** Логика генерации филворда

**Функции:**

1. **`generateWordSearch(words)`**
   - Генерирует поле 10×10
   - Размещает слова змейкой (максимум 1 поворот под 90°)
   - Заполняет пустые клетки случайными буквами
   - Returns: `{ grid, placedWords, failedWords, wordPaths }`

2. **`getRandomWordSubset(count)`**
   - Возвращает случайные слова из словаря (180+ слов)
   - Категории: IT, природа, еда, транспорт, дом, спорт, профессии, города, цвета, время

3. **`validateWordWithCoordinates()`**
   - Проверяет слово по координатам
   - Валидация: длина ≥3, границы поля, совпадение букв, наличие в словаре

4. **`extractWordFromGrid()`**
   - Извлекает слово из поля по координатам начала и конца

5. **`getDirection()`**
   - Определяет направление по координатам (horizontal/vertical/diagonal)

6. **`generatePath()`**
   - Генерирует полный путь координат между двумя точками

**Алгоритм размещения слов (змейка):**
```
1. Выбрать случайную стартовую позицию
2. Выбрать случайное направление (вправо/влево/вниз/вверх)
3. Разместить первый сегмент (2+ буквы)
4. Сделать поворот на 90°
5. Разместить второй сегмент (остаток слова)
6. Проверить границы и пересечения
7. Повторять до успешного размещения или 500 попыток
```

## 🎯 Ключевые фичи проекта

### 1. Многопользовательский режим
- 2-6 игроков в одной сессии
- Realtime синхронизация (polling + WebSocket)
- Уникальные цвета для каждого игрока

### 2. Боты с 3 уровнями сложности
- Лёгкий: медленный, много ошибок
- Средний: обычная скорость
- Сложный: быстрый, мало ошибок

### 3. Реванш
- Быстрое пересоздание игры после окончания
- Тот кто запросил — становится хостом
- Автоматическое присоединение хоста
- Баннер для остальных игроков

### 4. Командный режим
- 4 команды (красная, синяя, зелёная, жёлтая)
- Выбор команды перед игрой
- Подсчёт очков по командам
- Определение победителя команды

### 5. Игра на время
- Режим с лимитом 5 минут
- Таймер синхронизирован у всех игроков
- Автозавершение при истечении времени
- Сохранение статистики

### 6. Статистика и история
- История всех матчей игрока
- Количество найденных слов
- Время первого слова
- Занятые места

### 7. Аутентификация
- Email/пароль
- OAuth (GitHub, Google)
- Защита роутов
- Сессии 7 дней

## 🔧 Технические решения

### Почему tRPC?
- Полная типизация API (ошибки на этапе компиляции)
- Автодополнение в IDE
- Не нужен Swagger/OpenAPI
- Простая интеграция с React Query

### Почему Drizzle ORM?
- Лёгкий и быстрый (меньше Prisma)
- Полная типизация
- Поддержка миграций
- Прямой доступ к SQL при необходимости

### Почему Better Auth?
- Современная альтернатива NextAuth
- Простая настройка
- Поддержка OAuth из коробки
- Интеграция с Drizzle ORM

### Почему Clean Architecture?
- Разделение ответственности
- Легко тестировать (mock зависимости)
- Гибкость (легко менять реализации)
- SOLID принципы

### Почему polling вместо WebSocket?
- Совместимость с Vercel serverless
- Проще в реализации
- Достаточно для игры (обновление раз в 2 сек)
- WebSocket как опция для production

## ❓ Возможные вопросы на защите

### 1. Почему выбрали Next.js?
**Ответ:** Next.js предоставляет App Router, Server Components, оптимизацию из коробки (image optimization, font optimization), простоту деплоя на Vercel.

### 2. Почему tRPC вместо REST/GraphQL?
**Ответ:** tRPC обеспечивает полную типизацию API без необходимости писать Swagger спецификации. Ошибки обнаруживаются на этапе компиляции, есть автодополнение в IDE.

### 3. Почему Drizzle ORM вместо Prisma?
**Ответ:** Drizzle легче, быстрее, предоставляет более прямой доступ к SQL, лучше подходит для простых проектов. Prisma избыточен для нашего случая.

### 4. Как обеспечиваете realtime синхронизацию?
**Ответ:** Используем polling с интервалом 2 секунды через React Query. Для production планируется WebSocket. Текущего подхода достаточно для игры.

### 5. Как работает алгоритм генерации филворда?
**Ответ:** Слова размещаются змейкой (максимум 1 поворот под 90°). Алгоритм пробует случайные позиции и направления до 500 раз для каждого слова. Пустые клетки заполняются случайными буквами.

### 6. Как обрабатываете конфликты при одновременной отправке слов?
**Ответ:** Проверка на уровне БД — если слово уже найдено (есть в `foundWords`), возвращается ошибка. Транзакции обеспечивают консистентность.

### 7. Как работает реванш?
**Ответ:** При нажатии "Реванш" создаётся новая сессия с теми же параметрами. Игрок, запросивший реванш, становится хостом. Хост автоматически присоединяется, остальные видят баннер.

### 8. Как тестируете проект?
**Ответ:** 117 unit-тестов на Vitest покрывают 85%+ кода. Тестируем: бизнес-логику (GameService), генерацию поля, валидацию слов, миграции БД, схему БД, аутентификацию, DI Container.

### 9. Какие сложности возникли при разработке?
**Ответ:** 
- Реализация выделения змейки на клиенте (нужно отслеживать путь мыши)
- Синхронизация таймера между игроками (используем server-side endTime)
- Избежание дублирования статистики при завершении игры (уникальный индекс + проверка)

### 10. Что можно улучшить?
**Ответ:**
- Полный переход на WebSocket для realtime
- E2E тесты с Playwright
- Кэширование на стороне клиента
- Оптимизация размера бандла
- Поддержка разных размеров поля
- Наборы слов по темам
