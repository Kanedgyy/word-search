## Основные технологии

### TypeScript

**Версия:** 5.x

**Зачем нужен:**
- Статическая типизация — ошибки обнаруживаются до запуска кода
- Отличная поддержка в IDE (автодополнение, рефакторинг)
- Современный синтаксис JavaScript
- Легко поддерживать большой проект

**Альтернативы:**
| Альтернатива | Плюсы | Минусы | Почему не выбрали |
|--------------|-------|--------|-------------------|
| **JavaScript** | Проще для новичков | Нет проверки типов, больше багов | Мы делаем серьёзное приложение |
| **Flow** | Аналог TypeScript | Меньше сообщества, хуже поддержка | TypeScript популярнее |
| **Dart** | Статическая типизация | Другая экосистема, нужно учить новый язык | Мы используем экосистему JS |

**Вывод:** TypeScript — стандарт для современных TypeScript проектов.

---

### Next.js 16

**Версия:** 16.x

**Зачем нужен:**
- Фреймворк для React с "батарейками в комплекте"
- Встроенный роутинг (File-based routing)
- Server Components и Server Actions
- SSR (Server-Side Rendering) и SSG (Static Site Generation)
- API Routes для бэкенда
- Оптимизация изображений, шрифтов, скриптов

**Альтернативы:**
| Альтернатива | Плюсы | Минусы | Почему не выбрали |
|--------------|-------|--------|-------------------|
| **Create React App** | Простой старт | Нет SSR, нужно настраивать роутинг | Нам нужен SSR для SEO и скорости |
| **Vite + React** | Быстрее сборка | Нужно настраивать роутинг, SSR вручную | Next.js удобнее для fullstack |
| **Remix** | Отличный роутинг | Меньше сообщества | Next.js популярнее, больше ресурсов |
| **Nuxt (Vue)** | Аналог для Vue | Другой фреймворк | Мы используем React |

**Вывод:** Next.js — лучший выбор для fullstack React приложений.

### tRPC

**Версия:** 11.x

**Зачем нужен:**
- Полная типизация API (конец-в-конец)
- Автодополнение в IDE при вызове API
- Не нужно писать OpenAPI/Swagger спецификации
- Простота использования (как вызов локальных функций)
- Отличная интеграция с React Query

**Пример использования:**
```typescript
// На сервере
const router = createTRPCRouter({
  getUser: publicProcedure
    .input(z.object({ id: z.string() }))
    .query(({ input }) => {
      return db.user.findUnique({ where: { id: input.id } });
    }),
});

// На клиенте
const user = await trpc.getUser.useQuery({ id: '123' });
// TypeScript знает, что user имеет тип пользователя из БД!
```

**Альтернативы:**
| Альтернатива | Плюсы | Минусы | Почему не выбрали |
|--------------|-------|--------|-------------------|
| **REST API** | Стандарт индустрии | Нет типизации, нужно дублировать типы | tRPC удобнее для TypeScript проектов |
| **GraphQL** | Гибкий запрос данных | Сложность настройки, оверхед | tRPC проще для наших задач |
| **gRPC** | Высокая производительность | Сложность, требует .proto файлы | tRPC проще для веб-приложений |
| **AbortController** | Встроен в браузер | Нет типизации | tRPC лучше |

**Вывод:** tRPC — идеальный выбор для TypeScript fullstack приложений.

### Better Auth

**Версия:** 1.x

**Зачем нужен:**
- Современная библиотека аутентификации
- Поддержка OAuth (Google, GitHub, GitLab и др.)
- Email/пароль аутентификация
- Multi-factor authentication (MFA)
- Сессии и токены
- Легко интегрируется с Next.js

**Альтернативы:**
| Альтернатива | Плюсы | Минусы | Почему не выбрали |
|--------------|-------|--------|-------------------|
| **NextAuth.js (Auth.js)** | Популярная | Сложнее в настройке, больше зависимостей | Better Auth проще и современнее |
| **Clerk** | Очень простой | Платный для продакшена | Better Auth open-source |
| **Supabase Auth** | Хорошая интеграция с Supabase | Привязан к экосистеме Supabase | Better Auth универсальнее |
| **Passport.js** | Много стратегий | Старая, сложная | Better Auth современнее |

**Вывод:** Better Auth — современный и простой выбор для аутентификации.

## Библиотеки для работы с данными

### Drizzle ORM

**Версия:** 1.x

**Зачем нужен:**
- Типизированный ORM для TypeScript
- Легковесный (меньше Prisma)
- Быстрый (ближе к чистому SQL)
- Поддерживает PostgreSQL, MySQL, SQLite
- SQL-first подход (пишешь SQL, получаешь типы)
- Миграции из коробки

**Пример использования:**
```typescript
// Схема
export const users = pgTable('users', {
  id: uuid('id').primaryKey(),
  name: text('name').notNull(),
  email: text('email').unique(),
});

// Запрос
const user = await db.query.users.findFirst({
  where: eq(users.email, 'test@example.com'),
});
```

**Альтернативы:**
| Альтернатива | Плюсы | Минусы | Почему не выбрали |
|--------------|-------|--------|-------------------|
| **Prisma** | Популярная, хорошая документация | Тяжёлая, медленная, больше оверхеда | Drizzle легче и быстрее |
| **Kysely** | Отличная типизация | Меньше фич, нет миграций | Drizzle полнее |
| **TypeORM** | Поддержка многих БД | Старая, медленная | Drizzle современнее |
| **Чистый SQL** | Максимальная скорость | Нет типизации, больше кода | Drizzle даёт типы + скорость |

**Вывод:** Drizzle — лучший баланс между производительностью и удобством.

### Zod

**Версия:** 3.x

**Зачем нужен:**
- Валидация данных на runtime
- Типизация через inference
- Интеграция с tRPC
- Простой синтаксис
- Поддержка сложных схем

**Пример использования:**
```typescript
const userSchema = z.object({
  name: z.string().min(1),
  email: z.string().email(),
  age: z.number().min(18),
});

const data = userSchema.parse(input);
// data имеет тип { name: string, email: string, age: number }
```

**Альтернативы:**
| Альтернатива | Плюсы | Минусы | Почему не выбрали |
|--------------|-------|--------|-------------------|
| **Yup** | Популярная | Меньше TypeScript поддержки | Zod лучше для TS |
| **Joi** | Мощная | Сложная, старая | Zod проще |
| **superstruct** | Простая | Меньше фич | Zod полнее |
| **io-ts** | Функциональный подход | Сложная для новичков | Zod проще |

**Вывод:** Zod — стандарт де-факто для валидации в TypeScript проектах.

### Superjson

**Версия:** 2.x

**Зачем нужен:**
- Сериализация сложных типов (Date, Set, Map, undefined)
- Нужен для tRPC (передача сложных типов между клиентом и сервером)
- Прозрачная работа (не нужно менять код)

**Пример:**
```typescript
// Без Superjson
const data = { date: new Date(), set: new Set([1, 2, 3]) };
JSON.stringify(data); 
// {"date": "2024-01-01T...", "set": {}} // Date превратился в строку, Set потерялся!

// С Superjson
superjson.stringify(data);
// Сохраняет типы!
```

**Альтернативы:**
| Альтернатива | Плюсы | Минусы | Почему не выбрали |
|--------------|-------|--------|-------------------|
| **JSON.stringify** | Встроенный | Не работает с Date, Set, Map, undefined | Superjson лучше |
| **msgpack** | Быстрая сериализация | Требует библиотеку на обоих концах | Superjson проще |
| **BSON** | Поддержка многих типов | Тяжёлая, от MongoDB | Superjson легче |

**Вывод:** Superjson — необходимость для tRPC с сложными типами.

## Библиотеки для UI и стилизации

### Tailwind CSS

**Версия:** 3.x / 4.x

**Зачем нужен:**
- Утилитарные классы (не нужно придумывать названия классов)
- Быстрая разработка
- Адаптивность из коробки
- Маленький размер финального CSS
- Консистентные отступы, цвета, шрифты

**Пример:**
```html
<!-- Без Tailwind -->
<div class="card">
  <h2 class="card-title">Привет</h2>
</div>

.card {
  padding: 1rem;
  border-radius: 0.5rem;
  background: white;
  box-shadow: 0 4px 6px rgba(0, 0, 0, 0.1);
}

.card-title {
  font-size: 1.25rem;
  font-weight: bold;
  margin-bottom: 0.5rem;
}
```

```html
<!-- С Tailwind -->
<div class="p-4 rounded-lg bg-white shadow-md">
  <h2 class="text-xl font-bold mb-2">Привет</h2>
</div>
```

**Альтернативы:**
| Альтернатива | Плюсы | Минусы | Почему не выбрали |
|--------------|-------|--------|-------------------|
| **CSS Modules** | Локальные классы | Нужно придумывать названия | Tailwind быстрее |
| **Styled Components** | CSS в JS | Runtime оверхед, больше bundle size | Tailwind производительнее |
| **Bootstrap** | Готовые компоненты | Тяжёлый, узнаваемый дизайн | Tailwind гибче |
| **Chakra UI** | Готовые компоненты | Больше bundle size | Tailwind легче |

**Вывод:** Tailwind CSS — лучший выбор для быстрой и консистентной разработки UI.

## Инструменты для тестирования

### Jest

**Версия:** 29.x

**Зачем нужен:**
- Стандарт для тестирования JavaScript/TypeScript
- Отличная документация
- Snapshot тесты
- Coverage отчёт
- Моки из коробки

**Пример:**
```typescript
test('должен сложить два числа', () => {
  const result = add(2, 3);
  expect(result).toBe(5);
});
```

**Альтернативы:**
| Альтернатива | Плюсы | Минусы | Почему не выбрали |
|--------------|-------|--------|-------------------|
| **Vitest** | Быстрее, для Vite | Меньше плагинов | Jest стабильнее |
| **Mocha** | Гибкий | Нужно настраивать | Jest удобнее |
| **Jasmine** | Встроен в Angular | Меньше популярности | Jest популярнее |

**Вывод:** Jest — проверенный временем стандарт для тестирования.

## Дополнительные библиотеки

### React Query (TanStack Query)

**Версия:** 5.x

**Зачем нужен:**
- Управление состоянием сервера
- Кэширование запросов
- Background refetch
- Оптимистичные обновления
- Интеграция с tRPC

**Пример:**
```typescript
const { data, isLoading } = trpc.getUser.useQuery({ id: '123' });
// Кэширование, refetch, loading state — всё готово!
```

**Альтернативы:**
| Альтернатива | Плюсы | Минусы | Почему не выбрали |
|--------------|-------|--------|-------------------|
| **SWR** | Проще | Меньше фич | React Query полнее |
| **Redux** | Глобальное состояние | Оверхед для серверного состояния | React Query лучше для API |
| **Zustand** | Простой | Нет кэширования | React Query лучше для серверных данных |

**Вывод:** React Query — стандарт для управления серверным состоянием.

## Итоговая таблица выбора

| Категория | Выбрано | Альтернатива | Причина выбора |
|-----------|---------|--------------|----------------|
| Язык | TypeScript | JavaScript | Типизация, меньше багов |
| Фреймворк | Next.js 16 | Vite + React | SSR, API Routes, роутинг |

| Auth | Better Auth | NextAuth | Простота, современность |
| БД | PostgreSQL | MySQL | Надёжность, популярность |
| Валидация | Zod | Yup | TypeScript-first |
| UI | Tailwind CSS | Bootstrap | Гибкость, скорость |
| Тесты | Jest | Vitest | Стабильность, экосистема |
| State | React Query | Redux | Серверное состояние |
